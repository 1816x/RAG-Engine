# Aster Systems knowledge management prototype

Course project for MAPS, Challenge Phase 1. Aster Systems is a fictional software company; every document and identifier in this repository is synthetic.

## Contents

- `data/index.csv` and `data/documents/*.txt`: 32 labeled sample documents, eight each of Incident Report, Technical Guide, Test Procedure, and Release Note.
- `src/km_proto/core.py`: TF-IDF plus logistic regression classification and TF-IDF cosine retrieval.
- `src/km_proto/cli.py`: command line evaluation, classification, search, and demo.
- `model/aster_ontology.owl`: RDF/XML ontology with 13 classes, 11 object properties, five data properties, and linked examples from the corpus.
- `scripts/build_visuals.py`: generates the six-stage map, class-level conceptual graph, and PNG captures from execution logs. The PNGs are also embedded in the submitted PDF.
- `evidence/*.txt`: captured executions for evaluation, classification, search, and tests.
- `tests/test_core.py`: small behavioral checks for corpus integrity, holdout evaluation, classification, and retrieval.

## Run

Python 3.10 or later:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
PYTHONPATH=src python -m km_proto.cli demo
PYTHONPATH=src python -m km_proto.cli evaluate
PYTHONPATH=src python -m km_proto.cli classify --text "An operator reported a display error with logs and high priority."
PYTHONPATH=src python -m km_proto.cli search --query "How do we reproduce the session timeout?" --top-k 3
PYTHONPATH=src python -m unittest discover -s tests -v
```

On Windows PowerShell, activate the virtual environment with `.venv\Scripts\Activate.ps1` and set `$env:PYTHONPATH="src"` before running the module.

## Method and limits

The classifier fits a TF-IDF vectorizer and logistic regression on labeled text. Evaluation uses a stratified 24/8 split and three-fold cross-validation, fitting the vectorizer inside each training fold to avoid leakage. `classify` trains on all 32 examples for a new input. Its score is not a calibrated probability.

Search fits a separate TF-IDF vectorizer on all documents, transforms a natural-language query into that feature space, and ranks positive cosine similarities. This is lexical similarity with limited semantic reach; it will miss concepts expressed with unrelated vocabulary. A score of zero is omitted. Documents are fictional and intentionally small, so the evaluation does not predict performance on real organizational data.

Document categories correspond to OWL subclasses of `Document`. The CSV also identifies area and concept; the OWL file connects each document individual to those nodes and to incidents, systems, tests, or releases. The map shows a feedback loop from application to updated documentation.

## Rebuild artifacts

```bash
python scripts/build_ontology.py
PYTHONPATH=src python -m km_proto.cli demo > evidence/demo.txt
PYTHONPATH=src python -m km_proto.cli evaluate > evidence/evaluate.txt
PYTHONPATH=src python -m km_proto.cli classify --text "An operator reported a blank display with logs." > evidence/classification.txt
PYTHONPATH=src python -m km_proto.cli search --query "How can QA verify login session expiration?" --top-k 3 > evidence/search.txt
PYTHONPATH=src python -m unittest discover -s tests -v > evidence/tests.txt 2>&1
python scripts/build_visuals.py
```

The concept graph is generated by an equivalent diagramming script and can be compared with the OWL ontology. It is not claimed to be a Protégé screenshot.
